# Деплой MCP-сервера в Timeweb App Platform

## Структура проекта (минимальная)

```
restoplace-mcp/
├── server.js          ← код сервера
├── package.json       ← зависимости
├── Dockerfile         ← образ с EXPOSE 3000
├── docker-compose.yml ← опционально, можно обойтись без него
└── .gitignore
```

> **App Platform сам даст домен, настроит nginx и SSL.** 
> Свой nginx и certbot больше не нужны.

---

## Вариант 1 — Только Dockerfile (проще)

App Platform поддерживает деплой напрямую из Dockerfile без docker-compose. Это самый простой путь.

### Шаги

**1. Залей код в Git-репозиторий** (GitHub, GitLab или Bitbucket)

```bash
cd restoplace-mcp
git init
git add .
git commit -m "initial commit"
git remote add origin https://github.com/your-login/restoplace-mcp.git
git push -u origin main
```

**2. В Timeweb Cloud:**

- Раздел `App Platform` → `Создать`
- Тип приложения: `Backend`
- Во вкладке выбора фреймворка → переключись на `Dockerfile`
- Подключи GitHub/GitLab и выбери репозиторий
- Включи `Сборка по последнему выполненному коммиту` (автодеплой)

**3. Переменные окружения:**

Добавь в панели: `RESTOPLACE_KEY = твой_новый_ключ`

**4. Конфигурация сервера:**

Для этого MCP-сервера хватит самого младшего тарифа (512 MB RAM, 1 vCPU).

**5. Деплой:**

Платформа сама:
- клонирует репозиторий
- соберёт Docker-образ
- запустит контейнер
- настроит nginx на порт из `EXPOSE 3000`
- выдаст домен вида `your-app-xxxxx.twc1.net`
- поставит SSL-сертификат

## Вариант 2 — Docker Compose

Тоже работает, но с ограничениями. Используй этот вариант, если в будущем планируешь добавить базу данных или кэш в том же проекте.

### Ограничения App Platform для Compose

Согласно документации Timeweb:

- `Dockerfile` и `docker-compose.yml` должны быть **в корне репозитория**
- Проксирование настраивается **только для первого сервиса** в `docker-compose.yml`
- Запрещён режим сети `host`
- Некоторые директивы Docker Compose не поддерживаются (при попытке деплоя будет ошибка)

### Шаги

То же самое, что в Варианте 1, но на этапе выбора типа в панели:
- Тип приложения: `Backend`
- Переключись на вкладку `Docker` → `Docker Compose`

## Что изменилось по сравнению с обычным VPS

| Обычный VPS | App Platform |
|---|---|
| Ставишь Docker руками | Установлен |
| Свой nginx + certbot | Платформа даёт nginx и SSL |
| Сам настраиваешь домен | Готовый домен `*.twc1.net` из коробки |
| `docker compose up -d` вручную | Автодеплой при git push |
| Мониторинг ставишь сам | Дашборд с CPU/RAM встроен |
| Свой домен только через DNS | Можно привязать свой домен в панели |

## После деплоя

**1. Проверь что всё работает:**

```bash
curl https://your-app-xxxxx.twc1.net/health
curl https://your-app-xxxxx.twc1.net/tools
```

**2. Подключи URL в агенте:**

Панель Timeweb Cloud → твой AI-агент → MCP-серверы → Добавить → 
URL: `https://your-app-xxxxx.twc1.net`

**3. Добавь в промт агента инструкцию по бронированию** (см. предыдущие сообщения).

---

## Обновление кода

Просто делаешь `git push` — App Platform сам увидит коммит и пересоберёт контейнер. 
Никаких команд на сервере.

```bash
# Локально
git add .
git commit -m "update booking logic"
git push

# App Platform автоматически пересоберёт и передеплоит
```

---

## Минусы App Platform

- Данные в контейнере не сохраняются между деплоями (для нашего MCP это не важно — стейт он не хранит)
- Только публичные или подключённые через Git-провайдер репозитории
- Нельзя уменьшить размер диска в тарифе после увеличения

Для MCP-сервера этих ограничений не существует — он стейтлесс и данные не хранит.
